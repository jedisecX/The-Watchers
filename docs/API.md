# Bastion API reference

Generated by `scripts/gen_api_docs.py` from the application itself; do not edit by hand.
Machine-readable spec: [`openapi.json`](openapi.json).

## Conventions

* Base paths: user API `/api/v1`, administrative API `/admin/api/v1` (separate router, stricter controls).
* Auth: `__Host-bastion_sid` session cookie (browsers) **or** `Authorization: Bearer bst_…` personal access token (scopes `read`/`write`/`dm`). Sending both is rejected. Account-security and admin endpoints refuse tokens.
* CSRF: cookie-authenticated `POST/PUT/PATCH/DELETE` require `X-CSRF-Token` (from `GET /api/v1/auth/session`) and a same-origin `Origin`.
* Bodies: `application/json` only (except raw media upload), ≤ 64 KiB, strict parsing (duplicate keys, NaN, NUL and nesting > 32 rejected), unknown fields rejected (422).
* Errors: `{"error": {"code", "message", "request_id", "details?"}}`. Never stack traces. Objects the caller may not see return **404** (no existence oracle).
* Pagination: opaque `cursor`, `limit` 1–50 (default 20); response `next_cursor`.
* Rate limits: `429` + `Retry-After`. Buckets are adaptive by trust tier (anon/new/basic/established).

## WebSocket protocol (`/api/v1/ws`)

Client → server frames (anything else closes with 1008): `{"type":"ping"}`, `{"type":"subscribe","topic":"conversation:<uuid>"}`, `{"type":"unsubscribe",...}`, `{"type":"typing","conversation_id":"<uuid>"}`.

Server → client: `hello`, `pong`, `subscribed`, `error`, `notification`, `message`, `message_deleted`, `typing`. Close codes: 1003 binary, 1008 policy, 1009 too big, 1013 slow consumer, 4001 session revoked, 4003 account disabled, 4429 rate/connection limit.
